# 项目二操作手册：启动与板卡交互

更新：2026-10-04。按项目一启动手册的结构编写；命令依据当前项目脚本核对。开发板本轮未在线，本文没有把历史验收当作本轮实测。

## 0. 先分清电脑和开发板

本项目在 **Orange Pi 5 / RK3588 开发板** 上推理、拍照、录音和播放。摄像头、麦克风、音响应接在开发板上。Windows 电脑用于打开 SSH 终端、编辑文件和查看结果。

- 电脑项目目录：`<project-dir> RK3588-RKLLM 的离线端侧多模态智能体`。
- 开发板项目目录：`/path/to/project`。
- 看到 `PS C:\...>` 等提示符，说明还在电脑；SSH 登录后通常显示 `root@orangepi5:...#`。
- 命令框只复制命令，不复制提示符。除明确标为“电脑执行”的命令外，以下命令都在开发板终端运行。
- `cd` 是进入目录；`bash` 是执行脚本；`--npu` 使用板卡 NPU 后端，`--cpu` 使用板卡 CPU 后端。

**电脑上的“启动真实智能体.cmd”会启动 Windows 本地界面，它不控制板卡外设。做板卡项目请用下面的 SSH 入口。**

## 1. 一分钟启动

1. 给开发板供电，接好网线、摄像头、麦克风和音响，保持散热。
2. 在电脑项目根目录双击 **打开板卡项目二NPU测试.cmd**。连接地址为 `root@YOUR_BOARD_IP`；如果终端要求密码，输入板卡密码。密码输入时不显示字符是正常现象。
3. 菜单中先选 **6 环境自检**，再选 **1 中文对话**，输入“你好，请介绍一下你自己”。
4. 输入 `/quit` 回到菜单。选 **3 拍照并描述** 使用板卡摄像头；选 **2 语音问答** 时对板卡麦克风说话。
5. 测试结束，回到菜单输入 **0**，正常退出并释放模型。

快捷脚本中的临时密码助手可能已失效；这时在电脑 PowerShell 手动运行 SSH，按提示输入密码即可，不需要把密码发到聊天里：

```powershell
ssh root@YOUR_BOARD_IP
```

登录后执行：

```bash
cd /path/to/project
bash scripts/board_console.sh --npu
```

如果路由器重新分配了 IP，应使用板卡当前 IP；旧快捷方式地址也需要相应更新。

## 2. 菜单每一项做什么

| 选项 | 操作 | 如何确认 |
|---|---|---|
| 1 中文对话 | 输入文字，模型回答 | 能回答一般问题；`/reset` 清除本次聊天历史，`/quit` 返回菜单 |
| 2 语音问答 | 按当前配置录音（默认 5 秒），识别后确认，再回答并播报 | 检查识别文本是否正确，并亲耳确认扬声器声音 |
| 3 拍照并描述 | 从板卡摄像头采集图片并描述 | 对照实际画面判断描述，不能仅凭程序退出码认定识别准确 |
| 4 查询最近告警 | 读取配置指向的项目一告警库 | 对照事件 ID、时间和截图；旧事件不代表项目一此刻在运行 |
| 5 播放测试短句 | 在板卡音频输出上播放固定句子 | 亲耳确认音响，不以“设备存在”代替播放验收 |
| 6 环境自检 | 检查配置、依赖、模型和设备条件 | 阅读具体错误；通过自检不等于所有业务均验收通过 |
| 7 清空会话 | 清除会话上下文 | 不会卸载模型权重 |
| 0 退出 | 结束会话并释放相关模型进程 | 回到 shell 提示符 |

NPU 模式在首次请求加载语言模型，首次看图加载视觉模型；同一菜单会话复用进程，后续请求通常更快。取消、超时或 SDK 错误后，下次请求可能重新加载。不要为了每次提问重复关闭窗口。

普通聊天不会自动联网查天气，也不会自动拍照、录音。模型可能回答错误，需要结合实际场景检查。

## 3. 常用独立命令

先执行 `cd /path/to/project`。每条独立命令结束后会退出，若需要复用模型优先使用菜单。

```bash
bash scripts/run_linux.sh --npu doctor
bash scripts/run_linux.sh --npu chat
bash scripts/run_linux.sh --npu ask '你好，请用中文回答'
bash scripts/run_linux.sh --npu capture
bash scripts/run_linux.sh --npu record
bash scripts/run_linux.sh --npu speak '你好，这是板卡音响测试'
bash scripts/run_linux.sh --npu voice-once
bash scripts/run_linux.sh --cpu alarms --limit 5
```

录音或拍照命令会输出文件路径。使用实际生成的文件名替换下面的示例文件名：

```bash
bash scripts/run_linux.sh --npu transcribe inputs/你的录音.wav
bash scripts/run_linux.sh --npu ask '请描述图片' --image inputs/你的图片.png
```

图片应放在配置的 `input_dir` 下，默认是项目 `inputs` 目录；输入路径检查报错时不要关闭安全检查。

## 4. CPU、NPU 和两个项目共存

| 用法 | 启动方式 | 注意事项 |
|---|---|---|
| 项目二单独用 NPU | `bash scripts/board_console.sh --npu` | 使用 RKLLM 语言模型与 RKNN 视觉编码器 |
| 项目二用 CPU | `bash scripts/board_console.sh --cpu` | 使用 GGUF 模型；菜单启动时会启动 CPU 模型服务 |
| 项目一 NPU + 项目二 CPU | 两项目分别按各自手册启动 | 仍要协调摄像头独占、内存和散热 |
| 两项目都用 NPU | 暂不作为支持方式 | 曾实测驱动异常，保留现有互斥保护，不强行绕过 |

切换后端前，先从原菜单正常退出。`backend=rkllm_http` 本身不能证明使用 NPU：当前 CPU 配置也通过本机 HTTP 服务连接 llama.cpp；以启动参数和实际配置为准。

项目一检测、项目一 `camera_web.py` 预览与项目二拍照会争用同一摄像头。需要项目二拍照时，先在占用摄像头的原终端正常停止对应程序。查询已落库告警不要求项目一同时运行。

## 5. 外设配置与排查

在板卡列举设备：

```bash
ls -l /dev/video* /dev/v4l/by-id/
arecord -l
arecord -L
aplay -l
aplay -L
```

没有 `/dev/v4l/by-id/` 不一定表示摄像头不存在，继续核对 `/dev/video*`。采集节点也可能不止一个，不要把所有节点都当摄像头图像节点。

| 配置字段 | 用途 |
|---|---|
| `camera_linux` | 板卡摄像头节点，例如 `/dev/video0`；重插后可能改变 |
| `audio_linux` | 板卡录音输入，例如枚举确认后的 `plughw:CARD=设备名,DEV=0` |
| `audio_output_linux` | 板卡扬声器输出，和录音输入分别配置 |
| `audio_seconds` | 一次录音时长 |
| `tts_linux`、`piper_model` | 离线语音合成方式和模型路径 |

NPU 配置是 `config/rk3588-native.json`，CPU 配置是 `config/linux-cpu.json`。修改前备份，在板卡上编辑对应文件，再运行相应模式的 `doctor`。不要直接用电脑配置覆盖板卡配置；两边的设备和路径不同。

```bash
cp -p config/rk3588-native.json "config/rk3588-native.json.bak-$(date +%Y%m%d-%H%M%S)"
```

JSON 中字符串要保留双引号，不添加注释或多余逗号。如果提示填写 `camera_windows`，说明你正在运行 Windows 端程序，应退出并使用板卡 SSH 入口。

## 6. 项目一告警联动

项目二读取 `alarm_db` 指定的 SQLite 库，并在 `alarm_screenshot_dir` 下查找截图。**历史验收库和当前实时告警库不是同一概念**。先在板卡检查当前配置解析后的实际路径：

```bash
cd /path/to/project
.venv-linux/bin/python - <<'PY'
from edge_agent.config import load
for path in ('config/rk3588-native.json', 'config/linux-cpu.json'):
    c = load(path)
    print(path)
    for key in ('alarm_db', 'alarm_screenshot_dir', 'input_dir', 'camera_linux', 'audio_linux', 'audio_output_linux'):
        print(' ', key, '=', c.get(key))
PY
```

要看新告警，按项目一手册启动接收器和检测；把项目二 `alarm_db` 对应到接收器实际使用的 `--db` 路径，截图目录对应到实际截图位置，然后重新启动项目二查询。不要将某次 `evidence/soak_*` 验收库误认为实时库，也不要删除这些证据库。

联动验证应核对同一事件的 ID、时间、路号和截图，不能只检查“列表有内容”。若项目一正在使用 NPU，项目二采用 CPU 模式。

| 板卡路径 | 内容 |

| `/path/to/project/data/` | 业务数据、日志及测评结果，以实际子目录为准 |
| `/path/to/project/docs/` | 操作说明、验收证据和回退记录 |

在电脑 PowerShell 复制板卡某个文件，示例中的文件名要换成实际存在的文件：

```powershell
scp root@YOUR_BOARD_IP:/path/to/project/inputs/实际文件名.png "$env:USERPROFILE\Downloads\"
```

日常使用不需要重新执行 `bootstrap_linux.sh`、重新下载模型或复制整个 Windows 虚拟环境。首次新板部署/依赖修复才参照部署文档执行安装与构建。

## 8. 常见问题

| 现象 | 检查与处理 |
|---|---|
| SSH 超时 | 检查上电、网线、当前 IP 和同一局域网；模型配置不能解决网络不通 |
| 首次回答慢 | 首次加载与后续推理分开判断；保留同一菜单会话观察，不能仅凭等待时间认定卡死 |
| 摄像头打不开 | 检查节点、接线与其他进程占用；停止项目一预览/采集后再试 |
| 录音有文件但文字不对 | 真人说话测试，检查输入设备、距离和录音内容；静音文件也可能生成成功 |
| 播放完成却没声音 | 检查音响供电、接线、音量与 `audio_output_linux`，由人确认听感 |
| NPU 被占用 | 从另一项目原终端正常停止 NPU 工作，不删除锁文件或绕过保护 |
| 查询不到新告警 | 核对接收器是否落库以及两项目使用的数据库与截图目录 |
| SSH 下 GUI 无法启动 | 当前板卡入口是终端菜单；图形界面需要板卡真实桌面环境，Windows GUI 不能替代它 |

## 9. 停止与断电

聊天中输入 `/quit` 回菜单，再输入 `0` 退出。菜单内 Ctrl+C 通常取消当前操作后返回菜单，因此看到菜单后仍应输入 `0`。不要用关闭窗口代替正常退出。

退出后可只读检查进程；有输出时先确认是谁启动的，不要直接批量杀进程：

```bash
pgrep -ax edge-rkllm
pgrep -ax llama-server
```

准备断电时，先保存工作并正常停止两个项目，再在板卡执行：

```bash
sync
systemctl poweroff
```

SSH 断开后等待板卡完成关机，再切断电源。不要在模型写入、数据库写入或构建过程中直接拔电。

## 2026-10-05 语音识别更新

板卡 CPU/NPU 两种问答配置均改用 SenseVoice INT8 离线语音识别（语音识别本身在板卡 CPU 上运行，2线程；NPU 仍用于问答/视觉）。首次部署需安装 `requirements-asr.txt` 并运行 `python3 scripts/setup_sensevoice.py`；官方源无法连接时可加 `--mirror`，仍强制核对官方模型SHA256。模型位于 `models/sensevoice-int8`。

菜单2识别后：按回车确认；输入 `/r` 重录；输入 `/q` 取消；也可直接输入正确的问题。独立命令 `voice-once --confirm` 启用同样流程；不加 `--confirm` 保持原自动调用行为。

更新后先在旧菜单输入0退出，再重新进入菜单。已打开的旧进程不会自动加载新配置。两段“苹果是什么颜色的”原录音均通过，但不是全场景准确率保证；数字静音保护也不能代替完整的环境噪声检测。
