## 仍需改进的地方

| 优先级 | 发现 | 建议及验证方式 |
| --- | --- | --- |
| 中 | scripts/finish_recovery_audit.py的subprocess.run(timeout=...)只管理直接子进程；Linux超时强杀长稳脚本时，其finally不会执行，所启动的llama-server、项目一进程可能残留。属于代码级风险，本轮未用模型触发故障复现。 | 将自动测试放入独立进程组，取消/超时先发可处理的退出信号、等待回收，必要时仅终止该组；先用无硬件的父子进程夹具验证正常、超时、Ctrl+C与SIGTERM路径，再短测板卡。 |
| 中 | edge_agent/native_worker.py正常退出也直接terminate，Linux默认SIGTERM会绕过C++ Runtime析构，而不是先执行rkllm_destroy/rknn_destroy。既有退出检测通过，不代表这些析构函数执行过。 | 区分空闲正常关闭与正在推理的取消：空闲时先关闭stdin让服务循环正常退出，设置有限等待；超时再终止。验证正常退出码、回收及取消延迟不退化。 |
| 低 | edge_agent/runtime.py长期追加data/model-server.log，没有大小/保留数量上限。 | 增加有界日志策略，保留诊断尾部；用小阈值测试轮转、占用上限与Windows文件句柄行为。现有验收日志应单独保留。 |
| 中（证据） | 现有samples记录温度、RSS、NPU负载，没有CPU频率、热限频状态或节流计数；不能仅据此确认“全程未降频”。小时报告记录的是源码SHA，没有实际运行二进制及动态库SHA。 | 将已有结论限定为请求成功、温度范围、采样内存范围；以后运行时记录实际可执行文件、运行库、配置校验值，并补充频率/热状态采样。不要为补字段改写旧证据。 |
| 低（辅助脚本） | /path/to/project，后者依赖/tmp/verdict.py；换测试或临时目录被清理后可能读错结果或失效。 | 改为显式传入验收目录，辅助代码保存在项目内；测试目录不存在时失败，不用旧结果代替。 |
