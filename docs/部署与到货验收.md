# 部署与到货验收

目标硬件：RK3588 16GB + 32GB eMMC、原装12V电源、风扇、microSD、千兆网线、UVC USB摄像头、USB麦克风、音箱/耳机。具体板卡型号、系统镜像和音频设备尚未确认，不预设刷机镜像或修改内核。

## 到货前已准备

1. Windows 真实 CPU 语言/视觉模型、中文语音模型与独立 Python 环境。
2. 固定版 llama.cpp 源码和 GGUF 模型，可在 ARM64 Linux 构建 CPU 路径。
3. RKLLM/RKNN 原生 C++ 适配器、ARM64 运行库及固定 SDK 头文件，使用文件协议交接，不猜测 ctypes ABI。
4. 跨平台业务代码、模型超时/取消、采集失败恢复、只读告警查询、截图导入、设备设置和验收脚本。

## 仍未完成，不能冒充只缺硬件

- 官方预转换 NPU 模型所在 Lenovo Box 共享目录被自动审批拦截。已请求限定访问授权，未绕过。当前 models/rk3588 中没有已验证的官方配套模型。
- 本机没有可用 Linux 运行环境；Linux 构建脚本、ARM64 链接与实际 NPU 推理尚未实测。
- 摄像头/麦克风采集、实际扬声器播放、设备拔插、持续运行温度与速度，要在目标板上验收。
- 原生 NPU 适配器每次请求独立加载并释放模型，优点是超时/取消和资源回收清楚；代价是重复加载时间。没有把它描述为已经常驻优化的低延迟服务。

## 复制哪些内容

保留两个项目的相邻关系。项目二复制 edge_agent、config、scripts、tests、native、requirements.txt、models 下所用模型，以及 runtime/llama-source。使用 CPU 后端时保留 GGUF 两个文件；使用 NPU 时保留配套 RKLLM/RKNN 模型。

不要把 Windows 的 .venv 当作 Linux 环境使用；不要将 Windows exe 当作 ARM64 程序。下载 zip、未完成的 .part、Windows 引擎不需要占用板卡 eMMC。配置路径相对配置文件解析。

若缺少固定源码目录，可在有网络的电脑执行 `python scripts/setup_assets.py --source`；它验证归档后解压，不直接执行下载的代码。

## Debian/Ubuntu ARM64 准备

先核对板卡厂商镜像、aarch64 架构、Python 3.10+ 和可用空间。系统依赖为 python3-venv、python3-tk（仅GUI）、build-essential、cmake、ffmpeg、espeak-ng、alsa-utils、libgomp1；设备枚举可额外使用 v4l-utils。

脚本不会替用户刷机、修改驱动、写调频节点或关闭安全设置。它遇到缺依赖会输出清单。

```bash
bash scripts/bootstrap_linux.sh --cpu
bash scripts/run_linux.sh --cpu chat
```

CPU 后端可以先验收业务，不依赖 NPU 驱动，但速度不能以电脑测试代替板端测量。

## NPU 模型安装与构建

瑞芯微官方说明要求视觉编码器与语言解码器配套。当前适配器固定使用 Qwen 的图像特殊标记，不能随意替换成其他模型家族。Qwen3-VL 官方转换示例采用448×448，但实际预转换文件尺寸必须核对；运行时会检查配置与 RKNN 输入形状是否一致。

获得可信的配套文件后运行：

```bash
python3 scripts/install_npu_models.py --llm /path/to/model.rkllm --vision /path/to/model.rknn --width 448 --height 448 --source "来源、模型版本与导出工具版本"
bash scripts/bootstrap_linux.sh --npu
bash scripts/run_linux.sh --npu doctor
bash scripts/run_linux.sh --npu chat
```

安装器拒绝覆盖不同的已有模型，记录文件 SHA256；这不替代模型兼容性验证。板端构建输出 native/build/edge-rkllm 与邻近 lib 目录。当前固定库依赖 libgomp.so.1、libstdc++ 等系统库，不需要把 SDK 库覆盖到 /usr/lib。

## 到货验收顺序

| 步骤 | 操作与通过标准 |
|---|---|
| 1 基础环境 | 确認板卡型号、系统版本、内存/磁盘、散热风扇；运行 doctor，记录缺项 |
| 2 纯文本 | 运行 ask/chat，真实回答、算术正确、多轮与清空正常 |
| 3 静态图片 | 运行 scripts/acceptance.py --config 对应配置，几何图片识别正确 |
| 4 音频文件 | 加 --tts 完成本地合成文件→ASR；先不依赖外设定位软件问题 |
| 5 摄像头 | 用设备列表确认 UVC 节点和支持分辨率，填写配置，capture 得到可打开的图片 |
| 6 麦克风 | 确认 ALSA 设备，record 后检查WAV，transcribe 能识别实际说话 |
| 7 扬声器 | speak 明确指定一段短句，核对输出设备与音量，再测试语音问答 |
| 8 告警 | 项目一生成并落库后，项目二读取同一事件ID与截图；跨机器部署另核对截图同步 |
| 9 异常 | 拔插摄像头/麦克风、模型请求中途取消、进程重启与磁盘不足提示；无悬挂采集 |
| 10 持续运行 | 记录内存、温度、首字延迟和每秒输出速度；结合实测决定常驻模型与并行预算 |

这些步骤旨在缩短定位时间，不能保证硬件驱动、系统镜像或设备兼容问题一定能在固定时间内解决。
